# 工具安装记录读写保护

## 故障与处理

`tools.json` 包含安装版本、EXE 路径和检查时间。文件不存在表示首次使用;文件存在但无法读取、JSON 格式错误或缺少 `tools` 字段时,不能当成空安装记录。

- 列表加载失败时显示配置路径和错误,不再把所有内置工具标成“未下载”。
- 下载/更新前验证记录;写入事务内再次读取验证,损坏时拒绝覆盖。
- 后台版本检查仍允许网络失败静默,安装记录读写失败则显示错误。
- 支持 UTF-8 BOM,便于用户手动修复后用 Windows 编辑器保存。

## 写入协议

1. 取得同目录 `tools.json.lock` 的操作系统排他锁,覆盖跨线程、跨进程的完整读改写过程。等待上限 5 秒,每 25 毫秒重试;等待在阻塞线程池中执行。
2. 在锁内重新读取状态,只修改当前工具,避免不同工具并发下载/检查更新覆盖彼此记录。
3. 修改前的有效内容安全保存为 `tools.json.bak`。损坏内容不会覆盖备份;备份失败时不替换主文件。
4. 使用同目录、进程 ID + 序号命名且 `create_new` 打开的独立临时文件,完整写入并同步后重命名替换。
5. 替换失败只清理本次临时文件,绝不先删除主文件。锁句柄关闭或进程退出后由操作系统释放;锁文件保持存在。

备份保存的是**上一版有效记录**,不是安装目录副本,也不代表最后一次安装之前的历史归档。程序不会自动丢弃尾部字符、恢复备份或扫描 EXE 猜测版本。修复需要先退出所有 DevHub 实例,保留原文件并确认备份内容后再操作。旧版 DevHub 不遵循新锁协议,不要新旧版本同时运行。

文件锁使用 Rust 1.89 起提供的标准库 API。本次保护仅针对安装记录,不改变工具安装包的下载/解压流程,也不保证第三方编辑器同时改写配置时可以自动合并。

## 回归验证

- Rust: `cargo test --manifest-path src-tauri/Cargo.toml --lib tools::`
- 前端错误分类: `node --test tools/test-tool-errors.mjs`
- 前端构建: `pnpm build`

Rust 测试覆盖多余尾部对象、截断/非法内容、缺失文件、BOM、有效备份、较短内容替换、保存失败、锁超时、线程并发和独立进程并发。测试文件位于项目 `src-tauri/target/tools-state-tests` 下;独立进程辅助测试由父测试显式运行。
